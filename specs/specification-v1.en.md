# Training app: specification v1

**English** · [Português](especificacao-v1.md)

Date: 2026-10-20 · Version 1.18 (adjustments made during implementation are marked v1.1; new features are marked v1.2 to v1.18)

The Portuguese version is the reference used for the domain names in the code. Both versions must stay in sync.

## 0. Settled decisions

| Topic | Decision |
|---|---|
| Platform | PWA installed on the iPhone home screen; also opens in any browser |
| Data | On the device only (IndexedDB), with backup export and import. Sync is out of scope for v1 |
| Users | One per device, no login. Other people (men or women) use the app on their own phone; data is not shared (v1.3) |
| Plan | Generated by deterministic rules from the intake questionnaire (anamnesis), no AI |
| Restrictions | Pain never assessed by a professional triggers a recommendation to get it assessed; contraindicated exercises are substituted |
| Language | App UI in European Portuguese, English and Spanish (v1.8, F21); documentation in Portuguese and English |
| Methodology | SDD (this specification rules) + TDD in the domain + light DDD |

## 1. Domain language

These names are used identically in the specification, the code and the UI. The code uses the Portuguese term in brackets.

| Term | Meaning |
|---|---|
| **Anamnesis** (`Anamnese`) | Personal data, goal, availability, experience, restrictions and PAR-Q+ screening |
| **Restriction** (`Restricao`) | Body area with pain or limitation (shoulder, knee, lower back, wrist, hip, elbow) and usual intensity |
| **Exercise** (`Exercicio`) | Catalogue entry: name, primary and secondary muscle groups, type (compound/isolation), equipment, video link, purpose, contraindications, substitutes, load increment |
| **Plan** (`Plano`) | Ordered set of Workout templates generated from the Anamnesis, with the rules version used |
| **Workout template** (`TreinoModelo`) | E.g. "Upper A" (`Superior A`). A list of Prescriptions |
| **Prescription** (`Prescricao`) | Exercise + sets + rep range + target RIR + rest + note |
| **Session** (`Sessao`) | Actual execution of a Workout template on a date |
| **Set** (`Serie`) | Record of load (kg), reps and RIR |
| **Pain** (`Dor`) | 0–10 rating of an Exercise in a Session |
| **Measurement** (`Medicao`) | Body weight and waist on a date |
| **Progress photo** (`FotoAvaliacao`, v1.4) | Body photo on a date and in a pose (front, side, back), for personal comparison |
| **Profile** (`Perfil`, v1.4) | The person's name and photo, used in the greeting |
| **Suggestion** (`Sugestao`) | Load and reps proposed for the next Session (computed, not stored) |
| **Block** (`Bloco`, v1.2) | Cycle of progression weeks ending with a deload week; its length depends on the goal |
| **Deload** (`Descarga`) | Week with half the sets and RIR 3–4, to recover before the next block |
| **Achievement** (`Conquista`, v1.2) | Milestone computed from history (e.g. 10 workouts, 4 consecutive weeks met) |
| **Stretch** (`Alongamento`, v1.6) | Entry in the stretch catalogue: name, muscle group, position, one or both sides, steps, cautions and contraindications |

RIR = reps in reserve: how many more reps you could still have done at the end of the set.

## 2. Features and acceptance criteria

### F1. Anamnesis
- Fields: age, height, weight, waist, sex, goal (body recomposition, hypertrophy, strength, general health), days per week (2–7), session length (45/60/75 min), experience (beginner, returning after a break, intermediate), equipment (full gym, dumbbells only, home; since v1.17, a list, see F28), restrictions (painful areas, or "None"), accepts cardio (yes/no), PAR-Q+ (7 general questions). (v1.3) Plan emphasis (balanced, more legs and glutes, more upper body), for any sex. If sex is female: pregnancy or postpartum (no; pregnant, 1st trimester; pregnant, 2nd or 3rd trimester; postpartum, less than 12 months).
- **Given** I answer "yes" to any PAR-Q+ question, **when** I save, **then** I see a warning recommending medical clearance before training, and the plan is generated at conservative intensity and flagged as such.
- **Given** I report a restriction that has not been professionally assessed, **then** the app recommends an assessment, without blocking.
- (v1.3) **Given** I report pregnancy or postpartum, **then** the plan is conservative and a warning recommends follow-up with a doctor or obstetrician (and, postpartum, a pelvic floor assessment by a physiotherapist). In the 2nd and 3rd trimesters no exercise lying on the back or on the stomach appears.
- (v1.3) The pregnancy question only shows for female sex; changing sex to another value clears the answer.
- **When** I change the anamnesis, **then** the app asks whether to generate a new plan; history is kept.
- (v1.2) **Given** I tick "None" under pain or limitations, **then** every area is unticked, the plan uses the base exercises and there are no assessment warnings. Saving requires either "None" or at least one area.

### F2. Plan generation (rules in section 3)
- **Given** an anamnesis, **when** I generate the plan, **then** the result is always the same for the same input (deterministic).
- **Given** a shoulder restriction, **then** no exercise contraindicated for the shoulder appears; the first compatible substitute is used.
- **Then** each Workout template fits the declared duration (estimate in section 3.5).
- **Then** each Prescription shows a short reason (e.g. "replaces barbell bench press because of the shoulder").
- (v1.16) **Given** the equipment "At home, no equipment", **then** each workout has at least 4 exercises and the week trains chest, back, quadriceps, hamstrings and glutes (rules in section 3.9).

### F3. Today's workout
- The app proposes the next Workout template in the sequence (rotation, not weekday). I can pick another one.
- Lists the exercises with: name, primary muscle group, sets × reps, status (to do / in progress / done / skipped).
- At the top: a summary of the workout's purpose (e.g. "Upper A: horizontal push and pull; focus on chest and back").
- **Given** all exercises are done or skipped, **then** the session shows as **complete**, with skipped ones flagged.
- **Given** I close the app midway, **when** I come back, **then** the session in progress is as I left it.

### F4. Logging during the exercise
- Per set: load, reps, RIR (0–5). Values are prefilled from the Suggestion.
- Shows the previous session for that exercise ("last time: 20 kg × 10, 10, 9").
- At the end of the exercise: pain 0–10 (optional, default 0).
- Completing a set starts the Prescription's rest timer, with vibration/visual alert at the end (on iPhone, background sound is not guaranteed).
- A "substitute" button lists catalogue substitutes compatible with the restrictions.
- Large buttons, usable with one hand.

### F5. Exercise detail
- Primary and secondary groups, the exercise's purpose in 1–2 sentences, key technique points, contraindications.
- **When** I tap the video, **then** a player opens in an overlay inside the app.
- **Given** the video does not allow embedding or the link is not from an allowed domain, **then** an "open in YouTube/Vimeo" button is shown.
- (v1.2) Ads: the app does not block YouTube ads. The player belongs to YouTube, on another origin, and the app cannot change it; working around ads breaches YouTube's terms. Ad-free options: Vimeo links, or opening in YouTube with YouTube Premium.

### F6. Progression (rules in section 4)
- **Given** the history, **when** I open an exercise, **then** I see the Suggestion and its reason (e.g. "you did 12 reps on every set: go up to 22 kg").

### F7. Report 1: progression per exercise
- Chart of estimated 1RM (Epley, sets of ≤ 12 reps only) and best set per session.
- Personal record markers.
- Pain line per session for the same exercise.

### F8. Report 2: week in review
- Adherence: sessions done vs planned (last 4 weeks).
- Effective sets per muscle group vs target (section 3.3).
- Weight and waist trend (7-day moving average for weight).

### F9. Measurements
- Quick logging of weight and waist. Visual reminder after more than 7 days.
- (v1.5) Optional measurements: chest, arm, hip and thigh (cm), with instructions on where to measure. All of them appear in the photo comparison (F15).

### F10. Backup
- Export everything as JSON (and history as CSV). Import JSON with schema validation; an invalid file is rejected without changing any data.
- Visual reminder after more than 14 days since the last export.

### F11. Home (`Início`, v1.2)
- First tab of the bottom bar and the screen the app opens on. Minimal, read-only dashboard.
- Shows: workouts this week vs target (days per week), training hours this week and this month, streak of weeks met, next workout, block phase and next change (F14), this week's volume vs last week (load × reps), personal records this month, adherence over the last 4 weeks, weight trend (7-day average, change over 4 weeks), phrase of the day.
- Training hours: sum of end − start of finished sessions; each session counts at most 3 h (a session left open by mistake does not distort the total). Week runs Monday to Sunday; month is the calendar month.
- **Given** there are no sessions, **then** the dashboard shows zeros and the next workout, without errors.

### F12. Achievements and streak (v1.2)
- Computed from history, never stored; importing a backup recomputes them.
- Week met: finished workouts in the week (Monday to Sunday) ≥ the plan's days per week. Streak: consecutive weeks met up to the current week; the current week only counts once it is met and does not break the streak while it is in progress.
- Volume record week: volume (sum of load × reps) higher than every previous week, from the second week with workouts onwards.
- Achievements: first workout; 10, 25, 50 and 100 workouts; first week met; 4 and 12 consecutive weeks; first personal record; 10 personal records; first volume record week; one full block (at least one finished workout in every week of a block, deload included).
- The streak is weekly, not daily, because rest days are part of the plan.

### F13. Phrase of the day and reminders (v1.2)
- Home shows a short motivational phrase, picked deterministically from the date from a fixed list of Portuguese phrases.
- (v1.4) The phrase is shown in double quotes (“…”). When authorship is well documented, the author is shown below it (e.g. Juvenal, Fernando Pessoa, Lao Tzu). Phrases of doubtful or unknown authorship are shown without an author; proverbs are labelled "Provérbio".
- Reminders: user decision (2026-10-20): **no reminders**. Technical reason: on iPhone a web app cannot schedule local notifications, and push notifications require a server, which contradicts "data on the device only". Alternative assessed and not adopted: a calendar file (.ics) with a daily reminder, at a fixed time or 15 to 20 min before the usual training time.

### F15. Progress photos (v1.4)
- "Fotos" tab in the bottom bar.
- Add a photo: date (today by default), pose (front, side, back) and an optional note. The photo comes from the camera or the photo library.
- Before saving, the image is resized (longest side up to 1280 px) and re-encoded as JPEG. This reduces its size and strips metadata (including GPS location).
- Photos are grouped by month, newest first.
- Compare: I pick two months and a pose and see the photos side by side, each with the weight and waist of the closest measurement (up to 7 days apart) and the difference between them.
- Visual reminder after more than 30 days since the last photo. Tip: same light, same time of day, same distance.
- Photos stay on the device only. The JSON backup includes them (with a note that the file contains photos); the CSV does not.
- The app does not analyse the photos automatically (no AI); the analysis is the visual comparison with the measurements.
- (v1.5) "How to take the photos" guide: same time (morning, fasted), same light and plain background, phone at chest height about 2 m away, fitted clothing or swimwear, relaxed posture, all three poses, once a month.
- (v1.5) "Report for the PT" (PDF), from the comparison: for the two chosen months, the photos of each pose side by side, every measurement near those dates and the differences, training sessions and sets in the period, pain of 4/10 or more, and a blank space for the personal trainer's notes. The app gathers the material; the analysis is done by the professional. The photos go into the PDF exactly as stored (JPEG without metadata). The PDF is generated on the device and leaves it only if I share it.

### F16. Profile and greeting (v1.4)
- In "Mais": name (up to 40 characters) and profile photo (resized to 256 px, same processing as progress photos). Both optional.
- On Home: "Bom dia", "Boa tarde" or "Boa noite" (good morning/afternoon/evening), followed by the name if set, based on the device time: 5:00–11:59 morning, 12:00–19:59 afternoon, 20:00–4:59 evening. Shows the profile photo, if set.

### F17. Export plan and history (v1.5)
- In "Mais", an "Exportar" section: training sheet (current plan with exercises, groups, sets, reps, RIR and rest) and history (sessions, sets and measurements), as PDF, Excel (.xlsx) and JSON.
- PDF and Excel are generated on the device, with no external services or third-party libraries. The Excel file has the sheets "Ficha", "Histórico" and "Medições". The plan and history PDFs are text only; the only PDF with photos is the report for the PT (F15).
- The JSON for plan and history is the backup (F10).

### F18. Larger catalogue and muscle images (v1.5)
- Catalogue with at least 70 exercises, under the same rules (equipment, contraindications, substitutes).
- Each exercise shows a body drawing (front and back) with the primary group highlighted and the secondary groups in a lighter shade. The drawings come from the react-native-body-highlighter library (MIT licence, commercial use allowed; the licence notice ships with the code and appears in "Sobre" (About)). Female body if the sex in the anamnesis is female; male otherwise. Chosen by Guilherme on 2026-10-24 out of four compared options.
- New exercises may have no video: "Procurar no YouTube" (search YouTube) is shown and I can save the chosen link (existing feature).

### F19. Stretching (v1.6)
- "Alongar" (stretch) screen, opened from Home, from Today's workout and from the reminder at the end of a workout. It is not a new tab in the bottom bar, so the bar does not get cramped on the iPhone.
- Two modes:
  - "Do treino" (from the workout): one stretch per muscle group trained as primary in the workout, in exercise order, up to 6 groups. The workout is the last one finished in the past 12 hours; if there is none, the next workout.
  - "Por grupo muscular" (by muscle group): I pick a group, see the body drawing with that group highlighted (same library as F18) and every compatible stretch for it.
- Each stretch shows: the body drawing with the group highlighted, the dose (2 × 30 s; per side when it is one-sided), the written steps, the cautions, a timer for the hold, "Procurar no YouTube" (search YouTube) and "Mudar vídeo" (change video: a saved YouTube or Vimeo link, as for exercises).
- GIFs: not included. I found no collection of stretching GIFs with a clear licence for commercial use; the video and the written instructions cover the guidance.
- Rules: static stretching, to mild tension and never pain, 2 repetitions of 30 s per muscle (ACSM: hold 10–30 s, about 60 s in total per muscle). The app says honestly that stretching improves flexibility but does not prevent next-day muscle soreness (Cochrane review, 2011).
- Restrictions: a stretch contraindicated for an area marked as painful is not shown. In the 2nd and 3rd trimester of pregnancy, stretches lying on the back or front are not shown.
- Reminder: after finishing a workout, Today and Home show "Hora de alongar" (time to stretch), with the estimated time, until I choose "Feito" (done) or "Hoje não" (not today), which is saved in the session (and in the backup). It only appears for workouts finished in the last 12 hours. It is an in-app notice; there are still no notifications (F13).

### F20. Updates and what's new (v1.7)
- The app checks for a new version when it opens and every time it comes back to the foreground. On the iPhone the installed app often stays in memory, so checking only on open was not enough.
- The new version downloads in the background and waits. When it is ready, a "Nova versão disponível: X" (new version available) notice appears at the top of every screen (except while logging an exercise, so a set is not interrupted), with the summary of what changes and the buttons "Atualizar agora" (update now) and "Depois" (later).
  - "Atualizar agora" activates the new version and reloads the app. The data stays, because it is on the device and each set is saved when completed.
  - "Depois" hides the notice until the app opens again. If the app is closed completely, the new version takes over on the next open.
  - Offline, or with an invalid what's-new file, the notice appears without a summary ("Correções e melhorias.", fixes and improvements).
- In "Mais", an "Atualizações" (updates) card:
  - the installed version;
  - "Procurar atualizações" (check for updates), with the result: "Já tens a versão mais recente." (you have the latest version), "Nova versão pronta." (new version ready, and the button becomes "Atualizar agora") or "Sem ligação à internet. Tenta mais tarde." (offline, try later);
  - "Em preparação" (in preparation): what is being built or studied and has not reached the app yet;
  - "Novidades de cada versão" (what's new in each version): the history with each version's summary.
- After updating, Home shows "Novidades da versão X" (what's new in version X) once, with what changed since the last version seen, until I tap "Fechar" (close). The version seen is kept only on the device (it is not part of the backup).
  - It does not appear on a fresh install: for someone who has just arrived nothing has changed.
  - Someone who used the app before 1.7 sees the 1.7 notes.
- The summary comes from `src/novidades.json`, which every change with new features updates. The newest version in that file is the app version and must match `package.json`.
- It is an in-app notice, visible while the app is open. There is no notification while the app is closed: on the iPhone that needs push notifications and a server (F13).
- Moving from 1.6: 1.6 has no notice, so 1.7 takes over on its own on the next open, like earlier versions; from then on new versions wait for "Atualizar agora".

### F21. Languages (v1.8)
- The app is in European Portuguese, English and Spanish: every screen, the workout names and summaries, the plan's warnings and notes, the progression suggestions, the exercise and stretch catalogues, the daily quotes, the achievements, the what's-new notes and the PDF and Excel exports. In the CSV the exercise names are translated; the column headers stay fixed so spreadsheets that already use them keep working.
- On first open the language follows the phone's: Portuguese for Portuguese (any country), Spanish for Spanish, English for everything else.
- It can be changed on the welcome screen and in "Mais" (More), card "Idioma · Language". The choice stays on the device only (it is not part of the backup) and applies straight away, without reloading.
- The stored plan does not change when the language changes: its names, warnings and notes are shown in the current language. So are exercise names in the history.
- The Portuguese text is the key: the code marks each text with `t('…')` and the translations live in `src/i18n/en.json` and `src/i18n/es.json`; catalogue texts live in `src/catalog/i18n/`. A test fails if any app text lacks a translation in either language, if the variables (`{n}`) differ, or if a translation is left over that is no longer used. So every new feature reaches all three languages at once.
- The translations were written without review by a native translator.
- The repository documentation stays in Portuguese and English.

### F22. Robustness and comfort while training (v1.9 and v1.10)
Improvements from the 2026-10-26 review. F22.9 to F22.13 shipped in v1.10.
- **F22.1 The app never goes blank.**
  - An exercise in the plan that the catalogue does not know is removed from the plan shown, with the warning "N exercise(s) in your plan no longer exist and were removed. To replace them, generate a new plan in "More".". This can happen after a new catalogue version, or with a backup imported from a newer version.
  - If a screen fails for any other reason, "Algo correu mal" (something went wrong) appears, with "Export backup (JSON)", "Reload" and the error details. The backup reads the database directly, so it works even when the screen is broken.
- **F22.2 One tap, one save.** While a set or exercise change is being saved, the "Complete set", "Finish exercise", "Skip", "Undo", "One more set" and delete-set buttons are disabled. A double tap saves only once.
- **F22.3 End of rest on the iPhone.**
  - Three short beeps play when the rest ends. The sound is scheduled when the rest starts and only plays with the app open and the phone off silent mode. Vibration still works where the browser supports it; iPhone Safari does not.
  - During a workout in progress (opened in the last 3 hours and not finished), the screen stays on where the browser allows it (iOS 16.4 or later). There are still no notifications while the app is closed (F13).
- **F22.4 The rest timer is not lost.** The rest timer shows at the top of every tab until it ends or is skipped; it no longer disappears when you change screen.
- **F22.5 Sharing files on the phone.** On a touch screen, the backup and the exports (PDF, Excel, CSV) open the system share sheet: Files, iCloud Drive, email. If the browser cannot share files, or refuses, the file downloads as before. Cancelling the share downloads nothing.
- **F22.6 Contrast and accessibility.**
  - In dark mode the accent blue becomes a light blue with dark text on it (7:1). The green for "done" and "Rest over" gets dark text.
  - The borders of text boxes and selects reach at least 3:1.
  - Buttons react to touch (they get lighter), with no movement when the system asks for reduced motion.
  - Keyboard focus has a visible outline.
  - The video and photo windows use `<dialog>`: the rest of the app becomes inert, Esc closes, and focus returns to the button that opened them.
  - The pain sliders announce "N out of 10".
- **F22.7 Checks.**
  - The end-to-end tests run on the simulated iPhone with both the Chrome engine and the Safari engine (WebKit).
  - The code passes `oxlint` (correctness and React hooks rules; the rule that forbids reading the date while rendering is off, because the app shows dates relative to today).
  - Publishing to GitHub Pages only runs after CI passes on the main branch.
- **F22.8 Photos kept separate.** Progress photos are read only on the screens that show them, not on every saved set.
- **F22.9 Kilograms or pounds.**
  - In "More" (and in the first questionnaire) you choose "kg" or "lb". The default is "lb" on a phone set to US English and "kg" everywhere else. The choice stays on this device only.
  - Loads and body weight are shown and typed in the chosen unit: set logging, suggestions, last time, Reports, Measurements, Home, Photos, the questionnaire, PDF and Excel. Body measurements stay in centimetres.
  - Data is always stored in kilograms, and so are the backup and the CSV. Changing the unit changes nothing that is already logged.
  - In pounds, progression (section 4.1) uses steps of 5 lb where the exercise goes up 2 or 2.5 kg, 10 lb where it goes up 5 kg and 2.5 lb where it goes up 1 kg (always multiples of 2.5 lb, at least 2.5 lb). With a light load it goes up half, rounded to 2.5 lb. The 10% drop rounds to 0.5 lb.
- **F22.10 Correcting a set.** Each logged set has "Edit" (✎): the row turns into load, reps (or seconds) and RIR fields, with "Save" and "Cancel". Values are validated as when logging.
- **F22.11 Undoing a delete.** Deleting a set is immediate and shows "Set N deleted." with "Undo", which puts it back in the same place. The message goes away when the next set is logged or when leaving the exercise.
- **F22.12 Languages on demand.** The English and Spanish translations and catalogues are only loaded when that language is chosen. They are then kept for offline use like the rest of the app.
- **F22.13 Drawn icons.** The bottom bar uses line-drawn icons (SVG) instead of emoji, looking the same on every phone and taking the tab's text colour.

### F23. Reserve, rest and landscape (v1.11)
First phase of the 2026-10-31 study.
- **F23.1 Reserve in seconds.** On exercises measured in time (plank, side plank, farmer's walk), instead of RIR you log the reserve: "+15", "+30", "+45", "+60" or "+" (more than 60 s), the seconds you could still have held. It is optional, like RIR.
  - The plan asks for "reserve +15–30 s", and "+30–45 s" when the prescribed RIR starts at 3 (re-adaptation, deload, pregnancy, limitations).
  - It is stored in its own field on the set, separate from RIR. Earlier backups stay valid.
  - The sets table, PDF, Excel and CSV show the reserve in seconds. Older sets of these exercises keep their RIR, shown as "RIR N".
- **F23.2 RIR 0 is failure.** On rep-based exercises RIR stays 0, 1, 2, 3, 4 or 5+, and 0 is shown as "0 (failure)". Progression still does not raise the load after a set to failure (section 4.1).
- **F23.3 Visible rest timer.** The rest timer and the stretching timer sit fixed at the bottom of the screen, above the bottom bar, instead of under the iPhone status bar. The content gets extra space at the bottom so nothing is covered.
- **F23.4 Portrait and landscape.** The installed app rotates with the phone. In landscape the content and the bottom bar respect the notch margins, the video fits the screen height and buttons keep their touch size.

### F24. Load type (v1.12)
Second phase of the 2026-10-31 study. Each exercise says how its weight is counted, and the load field's label says so.
- **F24.1 How it is counted.** By the catalogue equipment: dumbbells "per dumbbell" (label "Load (kg per dumbbell)"); barbell "total, including the bar" ("Total load (kg)"); machine and cable "what the machine shows" ("Load (kg on the machine)"); bodyweight has no load. The progression increments (section 4) already followed this convention and do not change.
- **F24.2 Exercises with more than one piece of equipment.** When the exercise allows more than one way of counting (e.g. dumbbells or machine), the exercise screen shows "How do you count the weight?". The choice is saved for that exercise and applies to later sessions. Without a choice, the first equipment in the catalogue applies.
- **F24.3 Records keep the way.** Each exercise logged in a session keeps how its weight was counted. The load suggestion only compares sessions counted the same way. Records from before v1.12 count as the exercise's default way (for dumbbells, the weight of one dumbbell).
- **F24.4 Plates per side.** On barbell exercises, "Enter plates per side" swaps the field for "Plates per side". The app adds the bar and shows, for example, "20 kg bar + 2 × 15 kg = 50 kg". The total is always what is stored, so progression and records compare like with like. The bar weight is chosen in "More": 20, 15 or 10 kg (45, 35 or 25 lb in pounds); 20 kg by default.
- **F24.5 Exports and backup.** The Excel history and the CSV have a column for the way of counting. The backup carries the per-exercise choices and the bar weight; older backups stay valid.

### F25. Training days, calendar and PDF of the day, week and month (v1.13)
Third phase of the 2026-10-31 study.
- **F25.1 Training days.** In the anamnesis, below "Days per week", I can choose the weekdays I train on (Mon to Sun). If I choose, there must be as many as the days per week. Changing the days does not generate a new plan. Older backups stay valid.
- **F25.2 Forecast.** With days chosen, the plan's rotation is placed on those days starting from the next workout (F3). If today is a training day and I have not finished a workout today, the next workout is today's. If I train on another day, the forecast readjusts itself, because it always starts from the last workout done. Without days chosen there are no dates: a "Next workouts" list shows in rotation order.
- **F25.3 Calendar.** In "Reports", the "Calendar" tab shows the month, with the previous and next months. Each day marks the workout done (✓), the planned workout (short name), today and deload weeks. Tapping a day shows:
  - a past day or today with a workout done: the workout, the exercises with every set (load, reps, RIR or reserve), pain, duration and stretching;
  - today, not done or half done: what is left, with the button to continue the workout;
  - a later day with a planned workout: the workout as it will be that week (sets × range, RIR, rest).
- **F25.4 PDF of the day, week and month.** In "More" and in the calendar. In the app's language.
  - Day: today's workout (or the next one), with sets × range, RIR or reserve, rest, the load suggestion, the last time and blank spaces to write load and reps by hand.
  - Week: the next 7 days with dates (with days chosen) or the next workouts in the rotation (without days), with spaces to write. Only each exercise's first workout carries a load suggestion, because the later ones depend on what I do.
  - Month: 4 weeks from this one, with each week's phase (re-adaptation, block and week, deload), the workouts and exercises, and the exercise swaps when a new block starts. No loads.

### F26. Custom exercises (v1.14)
Fourth phase of the 2026-10-31 study (delivery A of the own plan).
- **F26.1 Create and edit.** In "More", "My exercises" lists the exercises I created and has "New exercise". Each exercise has:
  - required: name, measure (reps or seconds), how the weight is counted (per dumbbell, total with the bar, what the machine shows, or bodyweight only) and main muscle group;
  - optional: secondary groups, load increment, "How to do it" (one point per line) and a video link (YouTube or Vimeo, as in F22).
  - The default increment comes from how the weight is counted: 2 kg per dumbbell, 2.5 kg total or on the machine, none for bodyweight.
  - They are not translated: they stay as I wrote them, in any app language.
- **F26.2 Where they appear.** They join the catalogue: the exercise screen, the load suggestion (section 4), the weekly volume (the main group counts 1 set, secondary groups 0.5), the muscle drawing, the workout stretches, the history and the exports treat them like catalogue exercises. The plan generated by the rules (section 3) never picks them.
- **F26.3 Using them in a workout.** "Replace exercise" also lists my exercises with the same main group and the same measure. They can also be chosen in the own plan (F27).
- **F26.4 Deleting.** An exercise with no records is deleted. An exercise with records is archived, after confirming: it leaves the list and "Replace exercise", but the history, reports and exports still show its name. Once it has records, its measure cannot change, so reps and seconds are never mixed.
- **F26.5 Backup.** Custom exercises are included in the backup (F10). Earlier backups remain valid.

### F27. Own plan (v1.15)
Fifth phase of the 2026-10-31 study (delivery B).
- **F27.1 Create.** In "More", "Create my plan" opens the editor with the current plan as the starting point: the same workouts and exercises (those of the current block), sets, range, RIR and rest. With an own plan, the button is "Edit my plan".
- **F27.2 Edit.** I can change the name and order of the workouts, add workouts (up to 7) and delete them, and in each workout add exercises from the catalogue or my own (F26), reorder and delete them, and change sets (1–10), the reps or seconds range, RIR (0–5) and rest. A newly added exercise comes with the values of the rules for my goal (section 3.2): 3 sets, the compound or isolation range and RIR, and the rest. Each workout needs a name and at least one exercise (up to 20).
- **F27.3 Re-adaptation and deload.** On by default: 2 re-adaptation weeks (2 sets, RIR 3–4) and a deload week at the end of each block (half the sets, RIR 3–4), with the block length of my goal. I can choose 0 to 4 re-adaptation weeks, turn the deload off and choose blocks of 3 to 8 weeks. Saving keeps the week count and the workout rotation; with "Restart the count today", re-adaptation and blocks count from today.
- **F27.4 Differences from the generated plan.** Exercises are not swapped between blocks. Names stay as I wrote them, in any language. The questionnaire warnings (PAR-Q+, pregnancy, pain never assessed) remain, without saying the plan is conservative. When I add an exercise the rules would avoid (pain, pregnancy, equipment), the editor shows the reason but lets me choose it. Generating a new plan from the questionnaire replaces the own plan, after confirming.
- **F27.5 Own exercises in the plan.** Deleting an own exercise that is in the plan archives it (F26.4), so the plan keeps working.

### F28. Equipment list (v1.17)
Second phase of the calisthenics and home-training feasibility study (2026-10-31).
- **F28.1 List.** In the anamnesis, "What equipment do you have" is a list: barbell with plates and rack, dumbbells, pull-up bar, parallel bars or rings, weight machines, cable pulleys, resistance bands and ankle weights. Body weight always counts. The shortcuts "Full gym" and "Body weight only" tick and untick everything. A new anamnesis starts with everything ticked.
- **F28.2 Heaviest dumbbell.** With dumbbells, I can enter my heaviest dumbbell (optional, in the chosen unit). When the suggestion (section 4) would raise the load above it, it keeps the load and suggests taking 3 s to lower each rep or doing the exercise one leg or one arm at a time.
- **F28.3 Old answers.** An anamnesis without the list counts as: full gym = everything; dumbbells only = dumbbells; home = nothing. The generated plan is the same before and after the conversion, and the anamnesis opens with the list ticked. The old field is still saved as a summary (machines or pulleys = gym; otherwise dumbbells = dumbbells; otherwise home).
- **F28.4 Plan.** The plan only uses exercises with at least one ticked item or body weight (section 3.4). New exercises with bands (pulldown, face pull, biceps curl) and ankle weights (side-lying hip abduction, quadruped glute kickback) are added as the last substitutes of gym exercises. Bands and ankle weights have no logged load: progress is by reps and, at the top of the range, a heavier ankle weight or stronger band.
- **F28.5 Warnings.** Without a pull-up bar, dumbbells, bands or pulleys: back and biceps warning (section 3.9). Without a barbell or machines and with the strength goal: strength warning.
- **F28.6 Backup.** The backup keeps the list and the heaviest dumbbell; unknown equipment is rejected.

### F29. Holiday mode (v1.18)
Third phase of the calisthenics and home-training feasibility study (2026-10-31): keep training away from the gym, at home or outdoors, without losing the plan.
- **F29.1 Book.** In "More", "Holiday mode" › "Book a holiday": start date (today or later), end date (same day or later) and the equipment I will have, with the same list as F28 (body weight only by default). It lasts at most 8 weeks; for longer, the app suggests generating a new plan. It is on from start to end, inclusive.
- **F29.2 Adapt.** While it is on, each workout exercise (already with the current block's rotation) that cannot be done with the holiday equipment switches to the first compatible one: catalogue substitutes, then exercises of the same group and type, then of the same group, without repeating within the workout and with the same restriction and pregnancy rules. Sets and RIR stay; a replaced exercise (or one that loses its load) uses the body-weight range (section 3.9) or the catalogue's, and the note says "Holiday: replaces “…”". A position with no alternative is left out, with a warning. The saved plan does not change: logs stay in the same workout position, with the exercise actually done, and each exercise's progression continues from its own history.
- **F29.3 During.** "Today", "Home", the calendar, the PDFs and "Replace exercise" use the adapted plan. The plan's first warning says until when. Editing the own plan (F27) always starts from the saved plan.
- **F29.4 End.** At the end date, or with "End holiday" (or "Cancel holiday" if it has not started), the plan goes back to normal. The backup keeps the booked holiday.

### F14. Blocks and next change (v1.2, rules in section 3.7)
- On Home and on Today's workout: current phase (re-adaptation, week N of M of the block, or deload) and the next change with its date: end of re-adaptation (full sets), deload week (half the sets), or new block (isolation exercises rotate, listing what changes).

## 3. Plan generation rules (v1)

### 3.1 Split
| Days/week | Split |
|---|---|
| 2–3 | Full body A/B(/C) |
| 4 | Upper A, Lower A, Upper B, Lower B |
| 5 | Upper/Lower + Full body |
| 6 (v1.2) | Push A, Pull A, Legs A, Push B, Pull B, Legs B (A/B/C twice) |
| 7 (v1.2) | The 6 days + Active recovery (20 min easy walk and light core, 2 sets at RIR 3–4) |

With 3 days the split is Full body A/B/C rather than Push/Pull/Legs, because that split would train each muscle only once a week. With 7 days, the seventh is always a recovery day: strength training 7 days in a row is not recommended, especially when returning after a break.

Target frequency: each major group 2×/week.

**Choice of training template (v1.5).** In the anamnesis I pick the template; only combinations coherent with the days per week are shown:

| Template | Days | Workouts (in rotation) |
|---|---|---|
| Automatic (recommended) | 2–7 | Table above |
| Full body | 2–4 | Full body A, B (2 days) or A, B, C (3–4 days) |
| A/B: upper and lower | 2–6 | Upper A, Lower A (2 days) or Upper A, Lower A, Upper B, Lower B |
| A/B/C: push, pull, legs | 3–7 | Push, Pull and Legs A and B; with 7 days, plus Active recovery |
| By muscle group | 4–6 | Chest and triceps, Back and biceps, Legs A, Shoulders and core; with 5–6 days, plus Legs B |

- Combinations with 1×/week per group (A/B with 2 days, A/B/C with 3 days, By muscle group) are allowed, with a warning in the plan: evidence favours 2×/week (Schoenfeld et al., 2016).
- An incoherent combination (e.g. saved before changing the days) generates the automatic template, with a warning.

### 3.2 Parameters by goal
| Goal | Compounds | Isolation | RIR | Rest compounds / isolation |
|---|---|---|---|---|
| Recomposition / hypertrophy | 6–10 reps | 10–15 reps | 1–3 | 2 min / 60 s |
| Strength | 3–6 reps | 8–12 reps | 1–2 | 3 min / 90 s |
| General health | 8–12 reps | 12–15 reps | 2–3 | 90 s / 60 s |

### 3.3 Weekly volume
- Target: 8–14 sets per large group (chest, back, quadriceps, hamstrings, glutes), 6–10 per small group (shoulders, biceps, triceps, calves, core). The primary group counts 1 set; secondary groups count 0.5.
- The first compound for each large group in each workout gets 4 sets; the rest get 3.
- Note (v1.1): the minimum target went from 10 to 8 because, with 60 min and 4 days, 10 direct chest sets do not fit without cutting other groups. 8+ weekly sets remain in the range with good results (Schoenfeld et al., 2017).
- Re-adaptation phase (experience "returning" or "beginner"): weeks 1–2 with 2 sets per exercise and RIR 3–4; normal parameters from week 3.

### 3.4 Restrictions
- Each exercise has contraindications (e.g. `ombro`, shoulder) and an ordered list of substitutes.
- A contraindicated exercise is replaced by the first substitute without the same contraindication; if none exists, the exercise is removed and the group's volume is redistributed.
- Reintroduction (**not yet implemented**): an avoided exercise is only suggested again after 4 consecutive sessions with pain ≤ 2 on the substitute, always as an option, never automatically. In v1 it can be swapped manually via "Substitute exercise".

### 3.4.1 Sex, pregnancy and postpartum (v1.3)
- The base plan does not change with sex. With the same training, men and women gain strength and muscle in similar proportions (Roberts et al., 2020); automatically giving women more legs and men more upper body has no solid basis. The difference lies in the emphasis, chosen by each person (section 3.8).
- Pregnancy or postpartum: conservative plan (RIR 3–4) and a warning (ACOG, 2020). In the 2nd and 3rd trimesters, exercises marked in the catalogue as lying on the back or on the stomach (`deitado`) are replaced by the first compatible substitute, with the note "because of the pregnancy".

### 3.5 Duration
- Estimate per set: 45 s of work + prescribed rest. Warm-up: 8 min. Optional cardio: 10–15 min at the end of lower-body days.
- If the workout exceeds the duration, the last isolation exercise is removed first, then 1 set is cut from isolation exercises.

### 3.6 Cardio
- If accepted: 10–15 min at moderate intensity (able to speak short sentences) at the end of 2 sessions per week.

### 3.7 Blocks, deload and exercise rotation (v1.2)
- Block length by goal: strength 4 weeks (3 + deload); recomposition and hypertrophy 5 weeks (4 + deload); general health 6 weeks (5 + deload). Stored in the plan (`semanasBloco`).
- Weeks count from plan creation. With re-adaptation, weeks 1–2 are re-adaptation and the first block starts in week 3.
- Deload (last week of each block): sets = half rounded up, RIR 3–4, load stays the same (no increase).
- Rotation: at the start of each block, isolation exercises move to the next compatible alternative (catalogue substitutes, same restriction and equipment rules, no repeated exercise within a workout). Compounds stay, so progression stays visible. Alternatives are stored in the prescription (`alternativas`), and block n uses alternative n modulo the number of alternatives.

### 3.8 Emphasis (v1.3)
- Balanced: no changes.
- More legs and glutes: quadriceps, hamstring and glute compounds get 1 more set (max 5); upper-body and arm isolation exercises lose 1 set (min 2).
- More upper body: the reverse (chest and back compounds +1 set; leg and calf isolation −1 set).
- The duration adjustment (section 3.5) is applied afterwards.

### 3.9 Training at home (v1.16)
First phase of the calisthenics and home-training feasibility study (2026-10-31). Before, the "home" equipment produced workouts with 1 or 2 exercises, because the catalogue's substitutes were almost all gym exercises.
- **Equipment.** "Barra" is the barbell with plates. Pull-ups need a pull-up bar (`barra-fixa`), parallel-bar dips need parallel bars (`paralelas`) and the inverted row needs a pull-up bar or a bar in a rack. The gym has everything; "Dumbbells only" and "At home, no equipment" have none of these. Since v1.17, each person ticks what they have (F28).
- **Home exercises.** Added to the catalogue: decline push-ups, diamond push-ups, pike push-ups, one-arm backpack row, prone Y raise, sliding leg curl (towel) and wall sit. The single-leg Romanian deadlift can now be done without a dumbbell. Gym exercises get these as their last substitutes, so the choice at the gym does not change.
- **Body-weight range.** An exercise done with body weight only (no load possible, or the loaded equipment is not available) uses 8–20 reps for compounds and 12–25 for isolation exercises, for any goal, because with little load the stimulus comes from getting close to failure (Schoenfeld et al., 2017). The catalogue's own range still wins (e.g. plank 30–60 s, pike push-ups 6–15).
- **Warnings.** At home without equipment: back and biceps get little work, and a pull-up bar or dumbbells make the biggest difference. Without a gym and with the strength goal: the goal is limited without heavy loads.

## 4. Progression rules (double progression)

For each Prescription with range [min, max]:
1. If every set in the last session reached max reps with RIR ≥ 1: increase the load by the exercise's increment (barbell lower body 5 kg; barbell upper body 2.5 kg; dumbbells 2 kg; machine 1 plate or 2.5 kg) and go back to min reps. (v1.3) If the increment is more than 10% of the current load, increase by half the increment (rounded to 0.25 kg, minimum 1 kg). E.g. a 6 kg dumbbell goes up 1 kg, not 2 kg. This mostly helps people using lighter loads. For pounds, see F22.9.
2. Otherwise: keep the load and try +1 rep on the weakest set.
3. If below min reps in 2 consecutive sessions: reduce the load by 10%.
4. Pain ≥ 4: no load increase and a substitute is suggested. Pain ≥ 7: recommends stopping the exercise today and shows a warning to get assessed.
5. Re-adaptation phase: no load increase in the first 2 sessions of each exercise.
6. (v1.2) Deload week: keep the last session's load, no increase.
7. (v1.17) With dumbbells and the heaviest dumbbell entered (F28.2), the load does not go above it.

## 5. Non-functional requirements
- Works offline after the first visit.
- Opens in under 2 s on a recent iPhone.
- Light and dark mode, touch targets ≥ 44 px, text readable with the phone on the machine's holder.
- No analytics, no trackers, no network calls except videos and, on the app's own origin, the service worker and the what's-new file (F20).

## 6. Security
- Content Security Policy: `default-src 'self'`; `frame-src` only `https://www.youtube-nocookie.com` and `https://player.vimeo.com`; `img-src 'self' https://i.ytimg.com data: blob:` (v1.4: `blob:` to read the chosen photo before re-encoding it).
- Video links accepted only from youtube.com, youtu.be, m.youtube.com, vimeo.com; converted to embed URLs.
- iframe with `sandbox="allow-scripts allow-same-origin allow-presentation"` and `referrerpolicy="strict-origin-when-cross-origin"`.
- No data content is ever inserted as HTML.
- Import validated by schema (Zod). Photos accepted only as `data:image/jpeg;base64,` and with a size limit.
- (v1.4) Photos are re-encoded on the device before saving, which strips EXIF metadata (including GPS). They never leave the device except in the backup the person exports.
- Continuous integration: typecheck, `oxlint`, unit and end-to-end tests (Chromium and WebKit), `npm audit`; publishing only runs after CI passes (v1.9); Dependabot enabled. GitHub secret scanning applies to public repositories. Main branch protection: **not yet configured**.
- Personal data never enters the repository: the anamnesis is filled in on the phone and tests use a fictitious profile. That is why the repository can be public.

## 7. Out of scope for v1
Cross-device sync, notifications and reminders (on iPhone they need a server; no reminders by user decision), ad blocking, Apple Health, multiple users, AI, social features.

## 9. Example output of the rules
Fictitious profile used in the tests: recomposition, 4 days, 60 min, full gym, returning after a break, shoulder restriction, accepts short cardio.

- **Upper A:** neutral-grip dumbbell bench press, seated cable row, lat pulldown, light lateral raises, dumbbell curl, rope triceps extension.
- **Lower A:** leg press, Romanian deadlift, lying leg curl, standing calf raise, plank; 10 min cardio.
- **Upper B:** converging machine chest press, one-arm dumbbell row, neutral-grip pulldown, face pull, hammer curl, cable triceps pushdown.
- **Lower B:** goblet squat, hip thrust, Bulgarian split squat, seated leg curl, dead bug; 10 min cardio. (v1.1: the seated leg curl replaced the leg extension so hamstrings are trained 2×/week.)
- Weeks 1–2: 2 sets per exercise, RIR 3–4. Then: 3 sets, RIR 1–3.
- (v1.2) 5-week blocks from week 3: weeks 3–6 progression, week 7 deload; block 2 starts in week 8 and, for example, the dumbbell curl becomes a hammer curl and the rope extension becomes a cable pushdown.

The catalogue's video links can be replaced in the app with other YouTube or Vimeo links.
